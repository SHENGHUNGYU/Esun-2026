# 持股假說帳本與資產明細

工作台新增「持股與假說帳本」。選擇官方帳戶快照後，可查看資產、股數、收盤市值、權重、應收權益、假說時間線及未確認成交的每日候選回顧。

## 帳戶真值與損益

- 可交易股數、現金、可交易淨值、總資產、違規及提示直接來自 DataPack。
- 可交易市值 = 可交易股數 × 官方收盤價；權重以 `nav_tradable` 為分母。
- 相對初始資產變化 = 本期 `aum` − 已匯入的初始全現金 `aum`；變化率除以初始資產。沒有唯一初始值就不計算。這是未調整外部資金流的資產變化，不是個股歸因。
- 前份結算變化只比較已匯入的前份快照，日期會明列；不冒稱連續交易日報酬。
- DataPack 不含逐股取得成本，所以個股損益預設為未知，不以昨天收盤價或 D-Plan 預估價冒充實際成本。
- 可在頁面匯入成本 JSON 與原始證據。成本必須是該隊、該結算快照、該剩餘股數的總取得成本，含已分攤買進費用。可只提供部分股票；其餘維持未知。每個快照只保存一次，不覆寫；不同快照不能沿用舊成本。
- 成本標為「使用者提供，尚未獨立驗證」。未實現損益 = 收盤市值 − 剩餘取得成本；未實現損益率 = 損益 / 成本。未扣未來賣出費稅，不含應收權益。未建立已實現損益或完整公司行動成本分攤，不能據此宣稱完整交易歸因。

## 原始假說與跨日記憶

1. 匯入官方包後保存內容定址原檔與不可覆寫的結算事件。
2. 對前日候選驗證所有附件雜湊，再用官方結算股數對帳。只有唯一一致的本地假說可關聯，仍標為未驗證正式送出。
3. 首次觀測持股不必然是首次買入；只有可核對的 BUY 才稱為進場假說。缺少原始理由不倒填；多個候選雖股數相同但理由不一致時保留未知。
4. 原始假說包含理由、失效條件、推論、來源與因子證據。後續續抱、調整、退出另外記錄，退出後重新持有開新段落。
5. 每次新的 LLM 決策，CLI 依隊伍、結算日及資料截止時間凍結 `holding_memory_ref`。其他隊伍、未來結算、截止後才收到的資料、結算產生後才完成的候選都不作歷史依據。
6. 同日官方帳戶／持股／成交結果有衝突時，不任選一份重建該日假說。頁面明列衝突；仍可選原包查看其數值。
7. LLM 讀取壓縮的原始假說、失效條件與最近理由；有持股時，select 必須提供 `memory_review`，說明新證據是否支持續抱或退出，缺資料必須明列未知。沒有通過的回顧不能完成選擇。
8. 每份候選輸出 `holding-memory.json`（本次實際讀取的完整歷史）、`holding-review.json`（當日每股意圖、理由、失效條件、因子前後值及新增／缺漏／升降狀態、新聞證據、跨日回顧），納入 manifest 雜湊。這是候選意圖，次日結算才確認實際部位。

歷史模型文字只視為待檢驗信念，不當作系統指令、因果證明或績效保證。單日虧損與缺值不代表假說失效。現有成本、換手、風險與官方格式檢查持續生效。使用者補入的成本只用於明細顯示，不進入策略模型。

## 保存與相容性

- `artifacts/<執行根目錄>/holding-ledger/settlements/`：結算事件。
- 同目錄 `cost-basis/`：使用者提供且綁定快照的成本證據。
- 原始內容位於現有 `objects/`，讀取時驗證雜湊。
- 既有帳戶可回填索引，接收時間記為實際回填時間，不偽造歷史可見性。
- 既有候選、既有 D-Plan 均不修改；新版跨日回顧由下一次新流程開始產生。
- 程式版本已變更，舊的受阻工作應建立新執行版本，不能強行覆寫其封存輸入。

## 驗證

測試涵蓋成本缺值／股數及日期綁定、資產變化、空結算、跨日／跨隊／未來資料隔離、同日衝突、退出重新進場、LLM 接收凍結記憶、強制回顧、HOLD 完整產出與不重複模型呼叫的恢復，以及 API 讀取及成本保存權限。
