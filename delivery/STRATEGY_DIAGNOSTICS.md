# 選股排除、資產橋接與漸進非等權配置

工作台的「策略診斷與實驗」可選擇既有執行版本，使用已取得資料建立新分析。沒有下載、模型推論或正式交易副作用。分析會保存原來源、資料截止時間、程式版本、策略、參數及原始快照，並驗證輸出雜湊。

## 選股排除診斷

每次策略 evaluate 都記錄完整官方股票池，分為行情缺漏、前置排除、因子缺漏、篩選未過與已進入評分。另列排名、實際持有、目標持有與來源參照。新候選輸出 selection-diagnostics.json，LLM 可以看見缺值數量。

排名資格與持股不同：資料缺漏可以讓股票失去當日評分資格，續抱政策仍可能保留該股票。不能把缺值解釋成看空。已排名但未配置可能涉及產業、整張及續抱限制，報告不將它一律歸因為排名不夠好。

## 同期資產變化

以同隊兩份官方結算及同日期官方收盤價核對：

總資產變化 = 原股數 × 收盤價變化 + 股數變化 × 期末收盤價 + 現金變化 + 應收權益市值變化 + 未解釋差額。

已出清股票不在新 DataPack 時，需要額外的同日收盤價才能完整拆解。若缺價則明列差額；不填零。快照可能不相鄰，日期明列。

這是非還原價格的會計橋接，並非交易績效因果歸因。公司行動可能同時影響價格及股數。沒有成交明細時，不把現金變化當成已實現損益，亦不分離費稅、滑價、外部資金流或個股交易獲利。尚未提供同期指數／市值／產業基準歸因。

## 漸進配置

新增策略 mode=gradual，可由 LLM 自主提出與選擇。原有 rebalance、hold 等模式保留。

- 固定官方現有可交易股票籃子，不新買或出清名稱。
- 缺少本策略因子的股票維持原股數；不填補因子值。
- 在資料完整的既有部位間，以原投入市值分配 equal 或 rank_tilt 目標。
- 只有目標偏離免調整區間、買方分數高於賣方且訊號差通過門檻時，才做成對減碼／加碼。
- 買進金額由減碼淨收入支應，不動用原現金。費用與整張取整可能略提高殘餘現金。
- 預設最多兩組配對，每個代碼每日最多調整一次，每檔調整名目金額最多為 NAV 的 0.5%。不強制用完額度。
- 共用買賣合計 20% NAV、費稅 6bps、最小交易 0.3% NAV、權重免調整 0.3 個百分點、訊號差 0.15 的工程控制。這些不是經回測最佳化的參數。
- 繼續檢查現金、單股／產業限制、交易事件與九種價格壓力情境。沒有漸進模式的預算豁免。
- 對外輸出仍為官方 ADD／TRIM 及 BUY／SELL 股數；未變動股票列 no_trade_decisions。

## 實驗與正式選擇分開

離線報告比較 HOLD、FIXED_EQUAL、FIXED_RANK_TILT，固定同一股票籃子與初始現金。因子方案若完全沒有可評分股票，會明列改用同一來源先前已研究、覆蓋較完整的替代方案；兩個配置實驗共用該方案。這是資料可用性對照，不能稱為原策略改權重後的績效改善。

估算費用使用參考收盤價，正式成交均價尚未知。報告不呼叫模型、不產生 D-Plan、不表示 Agent 已採用。下一次新候選由 LLM 與續抱及其他方案比較後選擇，必須解釋交易必要性；不能以「續抱缺乏因子驅動」取代新證據。

命令列：

```sh
.venv/bin/python -m esun_research.cli --root artifacts/llm-agent-20261027 analyze-strategy --source-run <既有執行版本> --refresh
```

`--refresh` 只重新選取本地已取得的資料；不下載資料，也不修改原執行版本。產物在執行根目錄的 strategy-analysis/ 下。

## 決策理由及歷史一致性驗證

已有持股時，Agent 每評估一個換股方案，程式自動增加同因子 gradual＋rank_tilt 對照（ALT_ 識別）。全部對照都必須納入最終比較，但不算成另外一個新因子假說。選擇有交易方案必須另填 why_not_hold；選擇換股方案還須填 why_not_gradual。不再以「缺乏因子驅動」片語直接拒絕方案；選擇前強制完成證據綁定的持股及漸進檢查。逐筆排名與因子觀測透過 trade_evidence 提供；替換檔數與委託筆數分開，三組換股可產生六筆委託。這些驗證檢查論證結構與資料一致性，沒有證明未來報酬能抵銷成本。

買入與賣出理由分開產生；只有有因子評分時才提供 strategy_rank；逐股解釋及最終套用都檢查 BUY／ADD 不得寫成「超出續抱」。錯誤解釋會重試，仍失敗則受阻。

原始進場理由與失效條件由封存帳本直接複製到 history-audit.json，並依相同來源與原文分組。模型只能另寫當日解讀，不能重述或改寫歷史；缺少唯一歷史理由時保留未知。模型無法藉新的評論覆寫原始帳本。

為容納完整的七方案比較，本地模型上下文調為 16,384 tokens、輸出額度 3,072 tokens，模型名稱與 digest 保持相同。這只是推論容量設定；仍須保留逐輪大小紀錄及實際 token 用量。

Active Share 缺少同日完整基金持股、官方方法與日期確認，以及昨日候選來源不唯一等外部問題不會被上述修改自動標成通過。

昨日策略識別會優先使用截止時間前、綁定候選雜湊的使用者送出回報，並要求該候選股數與官方結算相符。後續若送出結果未知或無法對帳，就保留未知；不以回報冒充獨立官方查證。

BASE_PREVIOUS 只改對照識別與名稱，保留昨日策略的執行模式。昨日若為 hold，不要求憑空建立因子權重；若為 gradual，仍維持固定籃子及減碼淨收入支應加碼；risk_repair 仍須依當日既有違規決定是否需要修正。修正後建立新流程，不覆寫舊候選的程式雜湊與失敗紀錄。

在續抱比較中，交易方案必須引用至少一檔實際交易股票及其觀測方向。程式提供逐筆 trade_evidence，並將替換檔數與訂單筆數分開。所有文字論證仍屬待評估的模型判斷；這不是預期報酬或因果效果的認證。

股票代碼列舉在明確的股票、買賣與因子語境下視為識別碼，不當作財務主張。相同數字若用作價格、金額或報酬仍須通過數值驗證，不能靠股票代碼白名單放行。完整模型輸出及被拒絕的原因仍保留在 call 紀錄。

## 對續抱與交易採相同檢查要求

選擇前新增 review 階段，每批至多兩項同類問題。動能與外資同時負向，或在候選中被減碼的既有持股須檢查原始假說、失效條件、可見的前後觀測日期、反證及操作取捨。這是檢查觸發條件，不是賣出訊號。缺少原始假說只能標 unknown；兩個快照不能宣稱為連續每日趨勢。昨天續抱沒有使用因子時，仍保留最後一次可回源的逐因子觀測。

每個 gradual 方案須另比較續抱、漸進及其來源換股方案的實際委託、成本與殘留曝險；同因子排名只是當日評分，不是預期報酬。review 必須引用自己的輸入包，漏項、錯誤引用或修訂方案後未重查都不能 select。取消片語式自動改選誘因；修正回饋明確要求依證據判斷，不要求改成續抱或交易。

交付 decision-reviews.json／decision-reviews.md，包含原始假說、來源雜湊、模型判斷與取捨。被檢查個股的當日數值及檢查結論也進入 D-Plan 引用鏈。無因子方案不提供策略排名，說明模型若自行談名次會被拒絕。

已驗證續抱、換股及自動同因子漸進方案都能走完候選流程；漸進方案的 comparison_parent 先驗證來源及因子一致性，再納入重算比較，不會因來源標記而誤擋。這些是流程與證據一致性測試，不是策略績效驗證。
