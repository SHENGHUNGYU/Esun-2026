## 本輪目標與現況

目標：在一台已驗證的主機，從 TWSE／TPEx／中央社的真實資料生成可追溯、可恢復的中文研究報告，並證明資料缺失與模型失敗時仍能正確停止或降級。

目前已有 Python 套件、15 個啟用來源、不可覆寫原始檔、LangGraph、引用驗證與 checkpoint。前次紀錄為 9 項測試通過、既有官方樣本行情 150/150 檔通過；這些是既有證據，不能代替本輪的最新資料驗收。

六台主機已可 SSH 登入；模型框架與服務尚未驗收。公開 API 曾回應 HTTP 200，但完整傳輸逾時。FinMind 尚只有認證 transport，沒有可操作的歷史資料接入命令。預設 Python 除 3090 主機外均不符合目前專案要求；是否另有相容版本尚待盤點。

原規劃文件含有「競賽 Agent 尚未實作」「M3／GPU 尚未接通」等舊描述，應在本輪依證據更新，保留「研究管線已有初版、競賽決策與提交仍未實作」的區別。更新證據不等於使用者驗收完成。

## R02-2：解決真實公開資料下載

- 對應 U03；前置為至少一台可執行主機。
- Codex：以少量同一端點測試，比較目前本機、M3、3090 的完整下載與耗時，區分 DNS、連線、TLS、HTTP 回應及內容傳輸；不以 ping 或 HTTP 200 當作成功下載。
- 先完成 TWSE／TPEx 兩個核心行情端點，再測估值、主檔、營收、公告、財報與中央社 RSS，共 15 個已啟用來源。逐主機節流，避免為測試對全市場逐股重複抓取。
- 補齊逐來源進度、完整下載期限、串流大小上限、錯誤分類及安全重試。現有 75 秒 SIGALRM 僅適用 Unix 主執行緒，需驗證其停止行為；未證實前不將下載移到不相容的執行緒。
- 區分空資料、HTTP 失敗、截斷 JSON、schema 改變、新聞來源重導向與解析失敗；不盲目放寬主機白名單。
- 你的工作：如需校園網路／VPN，處理使用者端連線條件；不用手動下載資料代替正常流程。
- 驗收：15 個來源均有完整成功證據或具體失敗分類；兩市場核心行情必須完整下載及解析。至少完成兩次有間隔的完整抓取，記錄重複快照與修訂差異。
- 核心端點仍失敗則本輪資料驗收受阻；選用端點失敗可隔離，但對應能力必須關閉。
- 證據：`artifacts/rounds/R02/source-health.json`，包含來源、主機、開始／完成時間、耗時、bytes、hash、HTTP／schema 結果與錯誤原因；不保存 token 到日誌。

## R02-3：交易日、資料時點與能力矩陣

- 對應 U03；依賴 R02-2 的完整行情。
- Codex：接入並驗證官方交易日資訊，區分週末、假日、預期行情日與休市公告；尚無足夠權威資料時保留明確指定 as-of，不自動猜測。
- 逐一核對 150 檔行情日期、OHLC、成交量額、單位及市場映射；停牌／缺價須有明確狀態，不填零、不自行補前值當新行情。未建立可信停牌處理前沿用核心阻擋。
- 保留 first_seen、下載完成時間、發布時間、資料期間與修訂版本。新增測試：較晚才取得的舊期間資料不能進入較早 cutoff；相同內容重新下載不能被當成新事件。
- 改善能力矩陣：逐資料組、逐公司判定可用性，揭露分子／分母與排除理由。金融與一般產業分表不可當成同一張財報；本輪先驗收行情、官方估值與月營收增減率，財報比率仍維持關閉。
- 定義終態：BLOCKED 表示核心資料不成立；DEGRADED 表示核心成立但選用能力缺失；COMPLETE 僅表示本輪事先定義的必要能力全數通過。不得為消除 DEGRADED 而刪除真實缺口。
- 你的工作：審閱 5–10 檔樣本與至少一個休市／缺值／修訂案例。
- 驗收：150 檔逐檔對帳表、時間隔離測試、來源差異與 capability matrix 均可回源；無資料的能力不可生成數值。
- 證據：`artifacts/rounds/R02/data-quality.json`、案例與測試結果。

## R02-4：接通一個本地中文模型

- 對應 U02／U08；在 R02-1 盤點後選型，不先假設任何主機已有可用服務。
- 優先使用既有且授權合適的小型中文模型，選一個可用的 MLX／MPS 或 NVIDIA 後端；具體模型版本與框架於執行前核對官方模型卡、授權與相容性。大型權重下載先列明版本、大小、磁碟需求及主機。
- 先用 20 個可人工核對的中文案例，涵蓋否定、矛盾、數字／單位、時間、證據不足、壞 JSON、錯誤引用與惡意新聞指令。標籤由你審閱，不能讓被測模型自行定標。
- 保留程式產生數值事實、模型提出假說的分工。現有「禁止數字」檢查只是初步限制；數字改用中文仍可能錯誤，因此另做語意審查。
- 修正模型只取前 80 筆觀測的涵蓋風險：市場摘要、逐公司觀測、事件選取分層並記錄實際輸入 ID。報告揭露哪些公司曾交給模型；不得把有限輸入宣稱為全 150 檔模型分析。
- 使用遠端模型時由 SSH tunnel 接到 loopback；測量 timeout、總執行期限、重試耗時、記憶體峰值與版本。
- 建議驗收門檻：原始輸出至少 19/20 符合 schema 與引用規則；最終輸出全部合法或明確降級；關鍵否定／時間／注入案例不得有未攔截的高嚴重錯誤。實際成績與樣本量一併呈現，不能據此宣稱普遍準確率。
- 至少一份真實快照產生有證據的中文假說；模型不可用時仍生成事實摘要。模型延遲先量測再定服務目標，不以硬體規格臆估。
- 你的工作：提供既有模型位置（如有），審閱案例與錯誤；不需提供 API 金鑰。
- 證據：`artifacts/rounds/R02/model-eval.json`、提示詞 hash、模型版本、錯誤案例與人工審閱紀錄。

## R02-5：每日報告、重跑與故障恢復

- 依賴 R02-2／3；R02-4 失敗時以事實摘要驗收恢復能力，模型品質驗收另列受阻。
- 報告順序：資料狀態 → 市場摘要 → 公司變化 → 事件與風險 → 模型假說／反證 → 缺資料與禁止推論範圍。
- 將行情／營收事實、模型推論及未驗證資訊分開呈現；每筆數值與假說能追到來源 ID、原始列與時間。當天報告要說明比較依據；只有單次快照時不聲稱新增事件或環比變化。
- 增加穩定的 resume 入口，從保存的 request 恢復 cutoff、as-of 與版本，不讓預設「現在」導致同一 run-id 的參數衝突。
- 演練：下載截斷、RSS 失效、模型停機／逾時、錯誤引用、程序中斷、原始檔竄改、輸出竄改與重複執行；每項留下預期／實際行為。
- 同一封存快照恢復後，確定性產物 hash 應一致；模型使用已封存輸出恢復，另行重推論須建立新 run，不能宣稱模型重跑一定逐字相同。
- 將 fixture 與 live 的來源類型寫入 request／manifest／報告，避免只靠資料夾命名區分。
- 驗收：一份真實資料報告、一份模型失敗降級報告、一份核心缺失 BLOCKED 報告，以及可重現的 checkpoint 恢復紀錄。
- 證據：`artifacts/rounds/R02/research/` 與 `recovery-matrix.json`。

## FinMind 歷史資料：有條件支線

此支線不阻擋官方快照主線，也不以付費升級解決限制。

1. 先確認帳號可用資料集、額度與使用條件；token 只放指定執行主機的安全環境，不貼到聊天或網站。
2. 實作明確的歷史資料接入命令與參數紀錄；先用少量股票與短區間測試，再依額度評估擴展至 150 檔。不能因來源總清單有 73 個候選就全部抓取。
3. 區分價格、還原價、企業行動與對齊基準指數；尚未驗收前不計算正式 Beta／報酬排名。
4. 歷史下載時間與歷史發布時間分開。歷史財報目前最新版本不能直接作為當時已知資料；未取得 PIT 版本時，基本面回測明列不可用。
5. 若接通，交付歷史覆蓋率與缺值報告；若尚無 token，保留 mock transport 測試與明確阻礙，不把它列為成功。
